# KR-006 — Build parent authentication and sole-owner household foundation

## Goal

Let a parent securely create/recover/access their account and own empty device list.

## Context

Parent framework and Auth method are proposed in ADR-0001/PRODUCT. Household sharing beyond one creating owner is unapproved.

## Scope

After approvals, build native auth/logout/recovery states, verified account setup, idempotent household creation, secure session/cache handling, account deletion contract and tests.

## Out of scope

Child enforcement, household invitations, payments/social providers unless approved, dashboard controls beyond auth/empty foundation.

## Dependencies

KR-001, KR-002, KR-004 See [backlog](../ISSUES.md).

## Technical constraints

After approvals, build native auth/logout/recovery states, verified account setup, idempotent household creation, secure session/cache handling, account deletion contract and tests.
Follow linked ADRs and the repository task contract. No unapproved product assumptions or production gate bypass.

## Security/privacy

No password/session logs; enforce membership server-side; recovery and deletion must not become account takeover routes.

## Acceptance criteria

- [ ] AC-1: Owner approves framework/Auth/sole-owner decisions before bootstrap; stable tooling versions are verified and recorded.
- [ ] AC-2: Sign-up, verification, login, logout and recovery work with clear errors; no parent credential is ever transferred to child.
- [ ] AC-3: Repeated/retried creation yields one household and owner membership; editable metadata cannot self-promote.
- [ ] AC-4: Parent can read own profile/household and empty state; foreign/removed membership is denied even with an unexpired JWT.
- [ ] AC-5: Logout clears local sensitive data and documents session scope/token-expiry limits; child downloaded policy is unaffected.
- [ ] AC-6: Account deletion design includes reauthentication, revoke-before-delete and in-app/web request pathways with offline-child consequences.
- [ ] AC-7: Auth configuration/SMTP and sensitive logging are verified in test environment.

## Unit test plan

Auth UI reducer/loading/error/session-clear behaviours that have meaningful state transitions.

## Integration test plan

AUTH-01/02/04/05/06 and PRIV-03 with test Auth; duplicate bootstrap and expired tokens.

## Physical-device test plan

Login/recovery links, process recreation and secure storage on parent Android; large font/TalkBack.

## Failure-injection test plan

Network loss during verification/bootstrap/logout/delete, stale recovery link, SMTP errors.

## Observability

Redacted auth error codes and request IDs only.

## Definition of done

Authorized parent auth/household slice passes tests; no out-of-scope child control shipped.
Run relevant tests, record actual evidence, update source-of-truth docs/ADRs and list unrun checks.
Do not report completed merely because a plan exists.

## Done when

Authorized parent auth/household slice passes tests; no out-of-scope child control shipped.

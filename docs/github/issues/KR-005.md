# KR-005 — Validate single-use QR pairing and device-authentication protocol

## Goal

Complete the pairing/device identity threat model before final pairing implementation.

## Context

OD-09/10/20 and ADR-0003/0004 are accepted: opaque per-device credentials, five-minute single-use QR, 90-day credentials with day-30 rotation/five-minute overlap and revoke/fresh-QR recovery. OD-43 prospectively authorizes this local-only implementation, stacked on unmerged KR-004; no deployment or KR-006/007 GO.

## Scope

Implement the accepted authentication/TTL contracts and local transaction/protocol fixtures for redemption, single-use races, expiration, scoped identity, cancellation and interrupted delivery.

## Out of scope

Final QR UI/enrollment feature, production deployment, parent sessions on child, numeric fallback codes or custom cryptographic ceremony.

## Dependencies

KR-001, KR-004 See [backlog](../ISSUES.md).

## Technical constraints

Use accepted authentication/TTL contracts; build local transaction/protocol fixtures without reopening settled alternatives.
Follow linked ADRs and the repository task contract. No unapproved product assumptions or production gate bypass.

## Security/privacy

QR photo/front-running residual risk disclosed; no guardianship proof claimed; secret digest and TLS standard mechanisms.

## Acceptance criteria

- [x] AC-1: OD-09/10/20 outcomes are recorded; unapproved choices stay UNSPECIFIED.
- [x] AC-2: QR schema has opaque secret/session/version only and cannot redirect to attacker backend or expose parent JWT.
- [x] AC-3: Expired/replayed/cancelled/foreign-household requests fail and 20 concurrent claims create exactly one identity.
- [x] AC-4: Commit-before-response-loss produces consumed challenge and explicit incomplete-device revoke/fresh-QR recovery.
- [x] AC-5: Raw QR/device secrets never appear in test logs, error bodies, URLs or analytics.
- [x] AC-6: Device credential has only own-device routes and cannot become parent Auth or access siblings.
- [x] AC-7: Sequence diagram, token/credential lifecycle, rate limits and safe recovery are complete and consistent with BACKEND.

## Unit test plan

## Failure-injection test plan

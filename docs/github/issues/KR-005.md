# KR-005 — Validate single-use QR pairing and device-authentication protocol

## Goal

Complete the pairing/device identity threat model before final pairing implementation.

## Context

ADR-0003/0004 recommend opaque device credentials and five-minute QR capability; owner decisions are pending.

## Scope

Review authentication alternatives and TTL; build local transaction/protocol fixtures for redemption, single-use races, expiration, scoped identity, cancellation and interrupted delivery.

## Out of scope

Final QR UI/enrollment feature, production deployment, parent sessions on child, numeric fallback codes or custom cryptographic ceremony.

## Dependencies

KR-001, KR-004 See [backlog](../ISSUES.md).

## Technical constraints

Review authentication alternatives and TTL; build local transaction/protocol fixtures for redemption, single-use races, expiration, scoped identity, cancellation and interrupted delivery.
Follow linked ADRs and the repository task contract. No unapproved product assumptions or production gate bypass.

## Security/privacy

QR photo/front-running residual risk disclosed; no guardianship proof claimed; secret digest and TLS standard mechanisms.

## Acceptance criteria

- [ ] AC-1: OD-09/10/20 outcomes are recorded; unapproved choices stay UNSPECIFIED.
- [ ] AC-2: QR schema has opaque secret/session/version only and cannot redirect to attacker backend or expose parent JWT.
- [ ] AC-3: Expired/replayed/cancelled/foreign-household requests fail and 20 concurrent claims create exactly one identity.
- [ ] AC-4: Commit-before-response-loss produces consumed challenge and explicit incomplete-device revoke/fresh-QR recovery.
- [ ] AC-5: Raw QR/device secrets never appear in test logs, error bodies, URLs or analytics.
- [ ] AC-6: Device credential has only own-device routes and cannot become parent Auth or access siblings.
- [ ] AC-7: Sequence diagram, token/credential lifecycle, rate limits and safe recovery are complete and consistent with BACKEND.

## Unit test plan

Malformed QR, TTL boundary, payload bounds and scoped route tests.

## Integration test plan

PAIR-01–08 locally with transactional race tests and AUTH-03; no production enrollment.

## Physical-device test plan

QR scan usability can use synthetic mock; real secure storage tested in KR-007.

## Failure-injection test plan

Network loss before/after commit, cancellation race, replay, credential-return loss and abusive invalid attempts.

## Observability

Result codes and synthetic session IDs, no secrets.

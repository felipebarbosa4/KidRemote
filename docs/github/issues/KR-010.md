# KR-010 — Build minimal parent controls and child blocked/health UI

## Goal

Deliver the simple parent/child experience with accurate status and accessible controls.

## Context

Design system, five wireframes and three labelled concepts exist. They are not functioning app screenshots.

## Scope

MY DEVICES, detail +10/+30/Lock/Unlock/limit, QR status, loading/empty/offline/pending/errors/degraded/update states, minimal child blocked/help/permission screens.

## Out of scope

-10/-30 primary controls, dashboards/history, gamification, schedules, unapproved dark mode, store upload of generated mockups.

## Dependencies

KR-003, KR-006, KR-009 See [backlog](../ISSUES.md).

## Technical constraints

MY DEVICES, detail +10/+30/Lock/Unlock/limit, QR status, loading/empty/offline/pending/errors/degraded/update states, minimal child blocked/help/permission screens.
Follow linked ADRs and the repository task contract. No unapproved product assumptions or production gate bypass.

## Security/privacy

No screenshots of real child data; no optimistic success that masks enforcement failure; no status by colour alone.

## Acceptance criteria

- [ ] AC-1: Parent list/detail implement every required state with nickname, last reported time/lock reasons, freshness and health.
- [ ] AC-2: Controls reuse an operation ID on retry and create a new ID for a new intentional tap; server acceptance never renders observed lock prematurely.
- [ ] AC-3: At zero Unlock only reflects approved manual-lock semantics and +time helper copy; manual lock and expired reasons can coexist.
- [ ] AC-4: Pairing shows generating/QR/expired/error/success separately from permission-ready status; QR secrets clear on expiry/navigation.
- [ ] AC-5: Child blocked screen uses approved enforcement presentation and keeps verified safe help/recovery/system paths accessible.
- [ ] AC-6: Text/icon/colour communicate status; TalkBack/focus/large fonts and ≥48 dp targets work on physical devices.
- [ ] AC-7: Warm device-list useful render ≤1.5 s under stated conditions; backend error retains timestamped last-known data with retry.
- [ ] AC-8: Actual application captures replace/validate concepts before any store submission; privacy claims and Android-only scope match implementation.

## Unit test plan

Meaningful UI state transitions and accepted/pending/applied/degraded render models.

## Integration test plan

UI-01–03 with authenticated synthetic backend and failure fixtures; contrast/token checks.

## Physical-device test plan

TalkBack, 200% font, touch targets, small phone/tablet, offline/pending and child safe blocked presentation.

## Failure-injection test plan

Backend 5xx, stale list, lost ack, permission revoke, expired QR and repeat taps.

## Observability

Minimal UI loading/error timing; no session replay or interaction analytics collection.

## Definition of done

Approved minimal flows meet state/accessibility/performance criteria and use real verified backend/child outcomes.
Run relevant tests, record actual evidence, update source-of-truth docs/ADRs and list unrun checks.
Do not report completed merely because a plan exists.

## Done when

Approved minimal flows meet state/accessibility/performance criteria and use real verified backend/child outcomes.

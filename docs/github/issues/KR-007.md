# KR-007 — Implement child enrollment, scoped identity and permission-health setup

## Goal

Enroll a consenting native child installation with independent credentials and truthful readiness.

## Context

Pairing/auth threat model must be complete; enforcement setup follows approved KR-003 boundary.
OD-45 prospectively authorizes only local connected enrollment plus minimum parent QR/list
UI on unmerged PR #19. It is a development exception, not completion of KR-003/KR-006
physical gates or authorization for enforcement/physical installation/real use.

## Scope

Implement QR scan/redemption, identity persistence, first sync, separate permission consent/setup, health, rotation/revocation/re-pair and backup exclusions.

## Out of scope

Production enforcement timer, surveillance permissions, parent session reuse, arbitrary household moves, stealth removal resistance.

## Dependencies

KR-003, KR-005, KR-006 See [backlog](../ISSUES.md).

## Technical constraints

Implement QR scan/redemption, identity persistence, first sync, separate permission consent/setup, health, rotation/revocation/re-pair and backup exclusions.
Follow linked ADRs and the repository task contract. No unapproved product assumptions or production gate bypass.

## Security/privacy

Scoped secret only; no QR/JWT logs; no entitlement/permission auto-grant assumptions.

## Acceptance criteria

- [x] AC-1: Successful pairing creates exactly one correct-household identity and the child cannot call sibling/parent routes. Demonstrated locally through actual apps/HTTP/DB; not physical evidence.
- [ ] AC-2: Only foreground QR scanning uses camera; frames are not retained/uploaded and no photo-library permission is requested.
- [ ] AC-3: Credential bytes are wrapped by a Keystore key and excluded with identity/accounting from backup/device transfer; restore requires re-pair.
- [ ] AC-4: Permission refusal/revoke/incomplete setup is explicit; paired is not labelled enforcement-ready.
- [x] AC-5: Interrupted pairing follows approved consumed-token recovery and does not reissue a replayed secret. Actual commit-before-persistence fault, process restart and parent revoke/fresh-QR tested locally.
- [ ] AC-6: Credential rotation response loss is recoverable within the approved overlap; expired/revoked credentials cannot regain privilege.
- [ ] AC-7: Revocation/local removal behaviour and offline limits are visible; no downloaded policy silently disappears merely because network/auth expires.

## Unit test plan

Enrollment/setup/credential-lifecycle state transitions and route/payload validation.

## Integration test plan

PAIR-01–08, AUTH-03, DB-05/06, PRIV-01/02/03 against test backend.

## Physical-device test plan

Camera grant/refusal, Keystore restore failure, app restart/update/data clear, permission setup on supported devices.

## Failure-injection test plan

Lost redemption/rotation/ack response, revoked credential, corrupted local identity and offline reboot.

## Observability

Minimal enrollment/health/error codes; parent last-seen separates silence from healthy state.

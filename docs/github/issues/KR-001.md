## Goal

Turn the architecture proposal into an explicitly approved, testable MVP contract.

- [ ] AC-3: Given daily reset, limit reduction/increase, yesterday's delayed grant and simultaneous lock/grant, each transition has numeric expected state.
- [ ] AC-4: Owner explicitly approves or rejects OD-01–05/19; unresolved items stay UNSPECIFIED and dependent issues are blocked.
- [ ] AC-5: Screen-time definition, emergency/exempt-surface boundary and household timezone rule are explained in ordinary parent language.
- [ ] AC-6: All MVP/non-feature requirements map to acceptance/test IDs; no new monitoring feature appears.

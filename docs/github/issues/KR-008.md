# KR-008 — Build the persistent local screen-time accounting engine

## Goal

Account for permitted total usage and expire downloaded policy locally across normal lifecycle events.

## Context

Approved STATE-MACHINE/LOCAL-TIME and enforcement feasibility are prerequisites. Backend is not a clock.

## Scope

Pure reducer, monotonic signal adapter, transactional local persistence, minimal UsageStats reconciliation, daily reset, migration/reboot/clock uncertainty and adapter integration.

## Out of scope

Per-app history/limits, cloud countdown, exact WorkManager timer, unsupported anti-tamper guarantees, new policy choices.

## Dependencies

KR-001, KR-002, KR-003 See [backlog](../ISSUES.md).

## Technical constraints

Pure reducer, monotonic signal adapter, transactional local persistence, minimal UsageStats reconciliation, daily reset, migration/reboot/clock uncertainty and adapter integration.
Follow linked ADRs and the repository task contract. No unapproved product assumptions or production gate bypass.

## Security/privacy

Conservative uncertainty must preserve emergency/recovery; no package/content logging.

## Acceptance criteria

- [ ] AC-1: Eligible interactive/keyguard-hidden intervals count once; screen-off/locked/sleep/blocked-screen intervals do not consume allowance.
- [ ] AC-2: Used time/version/bonus/pending receipts survive normal process death, restart and app update without resetting.
- [ ] AC-3: Reconciliation covers only uncovered suffix; duplicate events/ranges never double-count.
- [ ] AC-4: Offline zero triggers approved safe restriction p95 ≤2 s on supported physical devices; no backend call required.
- [ ] AC-5: Reboot and offline reboot follow approved clock policy with no cross-boot elapsed subtraction or minted day from wall-clock/timezone edits.
- [ ] AC-6: DST/midnight split, limit change, manual-lock persistence and bonus expiry match approved fixtures.
- [ ] AC-7: Missing history/storage failure reports degraded state and approved recovery; no false precision or silent free allowance.
- [ ] AC-8: No per-app history is retained/uploaded; battery/checkpoint cost and recovery error are measured and accepted.

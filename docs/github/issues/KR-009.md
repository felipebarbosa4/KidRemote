# KR-009 — Implement idempotent control, sync, acknowledgements and FCM hints

## Goal

Deliver authenticated parent intent to local child execution with reliable convergence and honest status.

## Context

CONTRACT uses ordered desired state, immutable dated grants, absolute bonus and device receipts. Current FCM fid/token migration requires real integration evidence.

## Scope

Typed control API, transaction/outbox dispatcher, device sync/ack, FCM PushTransport/address adapter, retries/health and synthetic capacity test.

## Out of scope

Push as canonical command, always-high-priority silent messages, household topics, extra queue/DB, Realtime dependency, five-second delivery guarantee.

## Dependencies

KR-004, KR-007, KR-008 See [backlog](../ISSUES.md).

## Technical constraints

Typed control API, transaction/outbox dispatcher, device sync/ack, FCM PushTransport/address adapter, retries/health and synthetic capacity test.
Follow linked ADRs and the repository task contract. No unapproved product assumptions or production gate bypass.

## Security/privacy

No authoritative push payload, no service keys/client tokens in logs, strict target/actor checks and no sibling topics.

## Acceptance criteria

- [ ] AC-1: Every operation has unique ID, target, authenticated actor, server timestamp, ordering/version, payload and status; duplicate same payload returns original result.
- [ ] AC-2: LOCK/UNLOCK/SET_LIMIT latest desired state cannot be rolled back by stale delivery; ADD_TIME absolute dated total never applies twice.
- [ ] AC-3: Consistent snapshot/pagination and local persistence/adapter/ack seams pass CMD-01–15.
- [ ] AC-4: Push loss, process restart, resume and reconnect discover missed state without a particular push callback.
- [ ] AC-5: Current FCM HTTP v1 fid addressing is tested against chosen stable SDK/project; legacy-token fallback if needed is explicitly typed and justified by current docs.
- [ ] AC-6: Normal-priority hints are default; any high priority results in a real appropriate user-facing notification and follows documented restrictions.
- [ ] AC-7: Locally received grant persists ≤1 s; backend acceptance p95 ≤500 ms under defined load; duplicate/tenant errors zero.
- [ ] AC-8: Parent status distinguishes accepted/pending/persisted/applied/superseded/expired/failed, offline freshness and degraded enforcement.
- [ ] AC-9: Outbox/provider retry, registration replacement, invalid addresses, rate limits and revocation cannot lose canonical state or expose secrets.

## Unit test plan

Wire validators, version/epoch/period merge, idempotency and backoff error classification.

## Integration test plan

CMD/NET/DB tests and staged load plan with test Auth/device identities.

## Physical-device test plan

Real FCM addressing/delivery/permission background states and missed-push reconnect on supported Google devices.

## Failure-injection test plan

All push dropped, 429/5xx, dispatcher crash, network cut after commit, lost ack, out-of-order state and expired credentials.

## Observability

Latency stages, pending age, applied/enforcement failure codes, provider address kind/error; no raw addresses/secrets.

## Definition of done

End-to-end control converges under failures; current FCM compatibility evidenced; targets and limits accurately reported.
Run relevant tests, record actual evidence, update source-of-truth docs/ADRs and list unrun checks.
Do not report completed merely because a plan exists.

## Done when

End-to-end control converges under failures; current FCM compatibility evidenced; targets and limits accurately reported.

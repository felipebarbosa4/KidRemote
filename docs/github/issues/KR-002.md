# KR-002 — Verify the repository, agent map, documentation and CI foundation

## Goal

Make the planning repository safe and self-explanatory for the next bounded coding session.

## Context

The initial pass creates docs, ADRs, issue content, a validator, workflow and directory placeholders. This issue verifies the foundation and real CI after changes are committed.

## Scope

Review short AGENTS map, run planning checks, preserve links, validate Issue Form syntax, verify pinned checkout action/runtime and minimum workflow permissions, document missing build tools.

## Out of scope

Production app/backend implementation, deployment, arbitrary SDK version selection, unapproved branch rules or repository privacy changes.

## Dependencies

None. See [backlog](../ISSUES.md).

Review short AGENTS map, run planning checks, preserve links, validate Issue Form syntax, verify pinned checkout action/runtime and minimum workflow permissions, document missing build tools.

- [ ] AC-1: A new agent can navigate README → issue → spec/ADR → test plan and state Goal/Context/Constraints/Done when.

- [ ] AC-3: The workflow runs on pull_request and main push with contents:read, a verified full-SHA checkout pin and no persisted credentials.
- [ ] AC-4: GitHub Issue Form contains all required implementation sections using current syntax; its presence on the default branch is confirmed after merge.
- [ ] AC-5: Exact unchosen SDK/toolchain versions remain UNSPECIFIED; any required bootstrap pin has an official source/date.

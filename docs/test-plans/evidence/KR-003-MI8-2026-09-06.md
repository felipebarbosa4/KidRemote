## Established pre-fix causal finding

An ordinary-app Accessibility event may call `showOverlay()`. Attaching the Accessibility overlay may then emit an event associated with the spike package or another surface classified `SAFE_SYSTEM`; that event would call `hideOverlay()`. The exposed ordinary app could then emit a new event and repeat the cycle.

Status: **ESTABLISHED on this Mi 8 configuration** by owner observation and the sanitized trace below.

Owner observation: after the 10-second expiry, the restriction overlay flashed once and disappeared, leaving Calculator usable. Pressing Home,
and later opening another ordinary app then returning Home, could produce several further flashes while Home remained reachable. These observations
are a confirmed enforcement-stability **failure**, not a physical pass.

The Accessibility overlay itself emitted the own-package window-state event. The old resolver treated the spike package as a safe foreground
surface without distinguishing the attached enforcement overlay from the harness activity; it therefore removed the overlay. The later Home
flashes are not yet evidence for a Xiaomi-specific allowlist change and must be retested after the core fix.

## Bounded fix candidate

`SurfaceEventResolver` now preserves `ORDINARY_APP` only when all four facts hold: restriction is required, an enforcement overlay is attached,
the current underlying disposition is `ORDINARY_APP`, and the new event is `OWN_PACKAGE`. The service consequently keeps the overlay attached
and emits a debug-only `surface_preserved` trace. An own-package event without an attached overlay still resolves to `SAFE_SYSTEM`; a genuine
`KNOWN_SAFE_SYSTEM` event still resolves to `SAFE_SYSTEM`; and a missing identity still resolves to `UNKNOWN_FAIL_OPEN`.

No package was added to the safe list, and Accessibility collection was not broadened.

Pure JVM regression cases cover:

- attached-overlay own-package feedback while enforcing an ordinary surface → preserve `ORDINARY_APP`;
- genuine known-safe-system event → resolve `SAFE_SYSTEM`;
- own-package event without the enforcement overlay → resolve `SAFE_SYSTEM`;
- missing identity → preserve `UNKNOWN_FAIL_OPEN`.

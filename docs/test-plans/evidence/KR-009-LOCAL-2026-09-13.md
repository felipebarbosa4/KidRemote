## Scope and observed implementation

Parent JWT is verified by real local Auth; own-household operations use the existing KR-004 `accept_control` transaction through an invoker-rights HTTP RPC wrapper. UUID replay preserves the original actor/target/payload result. Expected versions protect LOCK/UNLOCK/SET_DAILY_LIMIT. ADD_TIME accepts only 600/1800 seconds and creates one immutable dated grant. Server transaction order/time is authoritative.

Credential-authenticated sync reads one consistent own-device snapshot: canonical version/policy, household zone/revision, trusted server UTC, current-period absolute bonus, and at most 100 ordered operation outcomes. `history_pruned` truthfully indicates omitted older outcome detail; the canonical snapshot still converges. This slice does not implement multipage history, delete historical command rows, or invent execution of omitted commands.

The child strictly validates JSON/schema/numbers/device/epoch, settles monotonic usage and commits the canonical policy and immutable pending ACK in the existing identity-bound Room ledger. Codec format 3 reads existing formats 1/2; Room schema remains 2 and migration 1→2 is unchanged. Duplicate/older policy cannot roll back version/usage. Existing A/B recovery remains authoritative. ACK retries preserve report sequence/body; server receipt time defines freshness. Parent status distinguishes accepted/pending/persisted/superseded/expired and rejected/failed outcomes. There is no enforcement adapter: `restriction_applied=false`, health `ENFORCEMENT_UNAVAILABLE`; persistence is never evidence of applied enforcement.

The child persists it using existing Keystore wrapping, then performs real sync/ACK HTTP and Room transactions.

## Method and source identities

Two same-signature debug app APKs are built from one recorded source commit, versionCode 1 and 2. They use the unchanged production Room schema 2 and reducer. They are laboratory builds, not the historical `609c0fd` binary or distributed releases. The CI bundle records source head, checkout merge head, package/version, APK SHA-256 and public signing-certificate digest; it contains no signing key or runtime data.

Scenario A prepares a real Room schema-2 ledger through the existing ChildAccounting/IdentityStore, then uses `adb install -r -t` for v1→v2. Scenario B separately prepares the same aggregate and disclosed legacy schema-1 SQL fixture already used by KR-008; real APK replacement precedes execution of the unchanged production `MIGRATION_1_2` under Room validation. Scenario B is not a claim that a historical schema-1 application was distributed.

The prepared aggregate has nonzero used time, policy version, absolute bonus, daily limit, manual lock, period key, cursor and HISTORY uncertainty. Private test oracles store digests/UID/PID/revision only, never raw identity/credential/policy contents. The encrypted identity digest must remain equal and decrypt successfully to the ledger epoch; UID, one ledger row and full payload digest must survive replacement before reconciliation. Controlled canonical fixtures then establish that covered intervals count zero and a new suffix counts once.

Migration observation wraps the exact production migration without changing its SQL or relaxing Room validation. A controlled kill occurs after its ALTER and before commit; old user_version, absence of the new column and identical payload demonstrate rollback. Retry and repeated opens distinguish two attempts (one interrupted) from exactly one committed migration. A missing migration path must throw while preserving schema/data. Actual APK downgrade is attempted without the downgrade override and must be rejected by Package Manager while v2/data remain installed.

Official contracts: [`adb install -r` retains data](https://developer.android.com/tools/adb); [Room migration validation and destructive-fallback implications](https://developer.android.com/training/data-storage/room/migrating-db-versions). Existing Room 2.8.5 remains selected; no dependency migration is introduced by current documentation examples.

## Implemented boundary

The gateway verifies the bearer digest and current device record before returning the
existing DEVICE_REVOKED type, now with exact protocol/device/epoch binding. Retired
old-generation credentials on an active device are credential rejection only. Unknown
credentials remain generic 401 without IDs. Existing SQL/locks/revocation transaction
are reused; no migration or new endpoint is introduced.

The child validates bounded own-sync 403 JSON (including duplicate/extra/foreign
fields), stores the validated envelope in its existing encrypted AtomicFile, and shows
removed/re-pair state. Only explicit clear of a readable, validated removed identity
removes its file/key. Missing-identity pairing recovery cannot clear an existing
unreadable identity. Offline/expired/unknown identity is retained, not auto-paired.
Removed state survives offline process restart and never claims healthy/enforcement.

The adapter still rejects configured/versioned policy; the app has no policy store,
ledger, snapshot ordering or applied-policy state. **Configured-policy persistence,
offline limits and retention on expiry are NOT_IMPLEMENTED / NOT_TESTED**, blocked
by later sync (KR-009; accounting KR-008). No fake policy blob substitutes for that
boundary. AC-7 stays unchecked/partial even if all local removal tests pass.

Reviewed official references (2026-09-13): [AtomicFile](https://developer.android.com/reference/android/util/AtomicFile)
provides atomic file replacement, not a multi-thread lock; the existing model serializes
operations on its executor. [Keystore](https://developer.android.com/privacy-and-security/keystore)
protects key material, not a compromised process. [Network security configuration](https://developer.android.com/privacy-and-security/security-config)
governs the retained debug-only local cleartext exception; this is not deployed TLS evidence.

## Implemented boundary

- A validates full bounded same-boot suffix coverage before changing aggregates; partial, shorter, unproven or contradictory coverage leaves durable use/policy/period intact and restricted. Replays consume only the uncovered suffix.
- B accepts canonical trusted input bound to existing identity epoch, household zone and revision. Strictly newer periods reset used time and old bonus once, preserve recurring limit/version/manual lock, and commit a new boot/monotonic/UTC anchor. Same-period deliveries, skipped dates, RTC/device-zone edits and reboot do not produce extra allowances.
- Existing Room schema 2/migration remains unchanged. Ledger payload format 2 stores the unresolved endpoint and highest observed boot. Legacy payload 1 remains readable; legacy uncertain records without an endpoint require B.
- A small CRC-checked write intent carries only epoch/revision/boot/endpoint flags. One process-wide lock serializes facade instances; Room revision distinguishes uncommitted recovery from a complete commit interrupted before intent cleanup. Writability alone never clears uncertainty. Corrupt storage/input fails closed.
- No package history, extra identity, credential, network trust acquisition or enforcement adapter is introduced. `restrictionRequired` expresses desired local restriction only.
